# FinSight Production Deployment & Environment Variable Guide

This guide provides a step-by-step reference for configuring environment variables and validating production deployments on **Vercel** (Frontend) and **Render** (Backend API, Analytics Service & PostgreSQL Database).

---

## 1. Vercel Dashboard Configuration (Frontend)

When deploying the `frontend/` directory to Vercel, set the following environment variables under **Project Settings → Environment Variables**:

| Variable Name | Environment | Required | Description | Production Example |
|---|---|---|---|---|
| `VITE_API_URL` | Production, Preview, Development | Yes | Public HTTPS URL of the Express backend API deployed on Render | `https://finsight-backend.onrender.com` |

### Vercel Project Settings Checklist
- **Framework Preset**: Vite
- **Root Directory**: `frontend`
- **Build Command**: `npm run build`
- **Output Directory**: `dist`
- **Install Command**: `npm install`

---

## 2. Render Dashboard Configuration (Backend, Analytics & Database)

### A. Managed Database (`finsight-db`)
- **Service Type**: PostgreSQL
- **Database Name**: `finsight`
- **User**: `finsight_user`
- **Internal Database URL**: Auto-generated by Render (used automatically when linking services or set in `DATABASE_URL`).

---

### B. Node.js Backend Web Service (`finsight-backend`)
- **Root Directory**: `backend`
- **Runtime**: Node
- **Build Command**: `npm install && npx prisma generate`
- **Start Command**: `npx prisma migrate deploy && node server.js`

| Key | Required | Value / Description | Example / Recommended Value |
|---|---|---|---|
| `NODE_ENV` | Yes | Application environment mode | `production` |
| `PORT` | Yes | HTTP listening port (Render assigns `$PORT` automatically; default fallback is `10000`) | `10000` |
| `DATABASE_URL` | Yes | Internal PostgreSQL connection URL from `finsight-db` | `postgres://finsight_user:password@dpg-xxx-a:5432/finsight` |
| `JWT_SECRET` | Yes | Random 32+ character secret string for signing access tokens | `prod_jwt_sec_89d3a7f8e12b4567c8901234567890ab` |
| `JWT_EXPIRES_IN` | No | Expiration duration for access tokens | `15m` |
| `REFRESH_SECRET` | Yes | Random 32+ character secret string for signing refresh tokens | `prod_ref_sec_99a2b5c7d12e3456f7890123456789cd` |
| `REFRESH_EXPIRES_IN` | No | Expiration duration for refresh tokens | `7d` |
| `FRONTEND_URL` | Yes | Production Vercel domain and preview URL patterns (comma-separated if multiple) | `https://finsight-frontend.vercel.app` |
| `ANALYTICS_URL` | Yes | Internal or external HTTP(S) URL of the Python analytics service | `http://finsight-analytics:8000` or `https://finsight-analytics.onrender.com` |
| `UPLOAD_DIR` | No | Storage path for file uploads | `./uploads` |
| `MAX_FILE_SIZE` | No | Max upload file size limit in bytes (10MB) | `10485760` |

---

### C. Python Analytics Web Service (`finsight-analytics`)
- **Root Directory**: `analytics`
- **Runtime**: Python 3.11+
- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`

| Key | Required | Value / Description | Example / Recommended Value |
|---|---|---|---|
| `ALLOWED_ORIGINS` | Yes | Allowed CORS origin(s) (Backend URL or Vercel Frontend URL) | `https://finsight-backend.onrender.com` |
| `PORT` | Yes | Assigned automatically by Render | `$PORT` |

## 3. Deployment Methods on Render

### Option 1: Automatic Infrastructure-as-Code (Render Blueprint)
1. Push this repository to GitHub.
2. In [Render Dashboard](https://dashboard.render.com), click **Blueprints → New Blueprint Instance**.
3. Select your repository. Render will automatically detect [`render.yaml`](file:///c:/Users/acer/OneDrive/Desktop/FinSight%281%29/render.yaml) and provision:
   - PostgreSQL database `finsight-db`
   - Express backend `finsight-backend`
   - FastAPI analytics service `finsight-analytics`
4. Fill in missing environment variables (`FRONTEND_URL`, `ANALYTICS_URL`) prompted during blueprint initialization.

### Option 2: Manual Dashboard Creation
1. Create PostgreSQL Database `finsight-db`.
2. Create Web Service `finsight-backend` pointing to `backend/` directory.
3. Create Web Service `finsight-analytics` pointing to `analytics/` directory.
4. Input environment variables manually according to the tables above.

## 4. Post-Deployment Validation Checklist

Execute the following steps after deployment to ensure high availability, security, and proper inter-service communication:

### Step 1: Backend Health Check & Database Connectivity
Run in browser or terminal:
```bash
curl -i https://finsight-backend.onrender.com/health
curl -i https://finsight-backend.onrender.com/api/health
```
**Expected Output**:
```json
HTTP/2 200
{
  "status": "ok",
  "service": "finsight-backend",
  "environment": "production",
  "uptime": "120s",
  "timestamp": "2026-08-17T22:00:00.000Z"
}
```

### Step 2: Analytics Service Health Check
```bash
curl -i https://finsight-analytics.onrender.com/health
```
**Expected Output**: `{"status":"ok","service":"finsight-analytics"}`

### Step 3: SSL / TLS Certificate & HTTPS Redirection
Verify that accessing `http://` automatically redirects to `https://` with a valid TLS certificate:
```bash
curl -I http://finsight-backend.onrender.com
curl -I http://finsight-frontend.vercel.app
```
**Expected Result**: `HTTP/1.1 301 Moved Permanently` or `HTTP/2 308 Permanent Redirect` pointing to `https://`.

### Step 4: CORS Preflight & Header Verification
Simulate an OPTIONS preflight request from Vercel domain to Render backend:
```bash
curl -i -X OPTIONS https://finsight-backend.onrender.com/auth/login \
  -H "Origin: https://finsight-frontend.vercel.app" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type"
```
**Expected Response Headers**:
- `Access-Control-Allow-Origin: https://finsight-frontend.vercel.app`
- `Access-Control-Allow-Credentials: true`
- `Access-Control-Allow-Methods: GET, POST, PUT, DELETE, PATCH, OPTIONS`

### Step 5: Full Authentication & SPA Routing Test
1. Visit `https://finsight-frontend.vercel.app/login` in your browser.
2. Direct reload (`F5`) on deep routes (e.g. `https://finsight-frontend.vercel.app/dashboard` or `/expenses`) to confirm `vercel.json` SPA rewrite rules work correctly without 404 errors.
3. Test user signup/login and check developer tools Network tab to ensure HTTP cookies / Bearer tokens are sent with `withCredentials: true`.
